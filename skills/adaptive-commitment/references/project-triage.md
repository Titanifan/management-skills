# Project Triage

Use this module for papers, R&Rs, grants, datasets, research platforms, industry projects, commercial pilots, and working papers.

## Project classifications

### Core arena project

Strengthens the user's central identity and helps define or deepen an arena. It should receive protected cognitive capital.

Typical mode: Own or Build.

### Platform asset project

Builds reusable theory, data, method, capability, partner access, student pipeline, software, dashboard, distribution, or policy legitimacy.

Typical mode: Build.

### Option project

Has material uncertainty and possible upside. It should receive a bounded commitment designed to produce decision-relevant information.

Typical mode: Option.

### Service or legacy project

Exists because of prior commitments, supervision duty, co-author relationships, or institutional service. Complete responsibly without consuming core attention.

Typical mode: Service-track or Delegate.

### Kill or exit project

Has weak value, no viable evidence or mechanism, no owner, negative evidence, or excessive governance burden.

Typical mode: Kill or Park.

## Stage assessment

For every active project identify:

- current stage: investigate, validate, build, scale, or reallocate;
- principal uncertainty;
- principal constraint;
- evidence needed for the next stage;
- resource floor and cap;
- next review condition.

Do not scale because a pilot produced an interesting result. Require evidence of repeatability, capability, ownership, and value.

## Project hard kills

- No mechanism or value-realisation pathway.
- No credible evidence or target audience.
- No identifiable owner.
- Fashionable but interchangeable topic.
- Excessive work for weak strategic return.
- User performs labour belonging to a student or collaborator.
- Project persists only through sunk cost.
- Option has no milestone, cap, or review condition.
- Negative evidence is repeatedly ignored.

## Milestone discipline

Examples:

- one-page theory and mechanism architecture;
- confirmed data access and quality check;
- pilot table, coding sample, customer interview set, or prototype;
- target audience and contribution validation;
- collaborator role agreement;
- proof that a student can independently deliver;
- evidence that a technology pilot creates operational or customer value.

If the milestone fails, follow the pre-defined downgrade, redesign, delegate, park, or kill rule.

## Portfolio output

For multiple projects, show:

- which deserve protected cognitive capital;
- which should remain bounded options;
- which should be delegated or service-tracked;
- which should be parked or killed;
- which compete for the same scarce resource;
- where reallocation would create the greatest strategic gain.
